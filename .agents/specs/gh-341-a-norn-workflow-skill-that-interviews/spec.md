## Observed

The only guide to writing a workflow is "copy a shipped one and edit it" (docs/recipes.md, "Write your own workflow"). Getting a workflow right takes knowledge spread across the schema, the validator and the docs: six step types (`agent`, `check`, `gate`, `git`, `slices`, `merge`) and their outcomes, a counter on every route back, `open-pr` between any code change and a gate or merge step the round can end from, `exits` per exit code, the `norn:wf:<name>` label `norn upgrade` creates, and a workflow being pinned when a unit starts. No skill covers it, so an agent asked to write a workflow guesses, and finds out only when a tick refuses the workflow. (norn 0.33.0)

## Wanted

A bundled skill, `norn-workflow`, that a person uses with an agent to create a workflow or change an existing one:

1. Interviews the person one question per turn, each with a recommended answer: the kind of work, which steps need a person (gates, attended steps), which checks run, where a failure goes back to and how many times, and whether the round ends at a PR, at the merge, or neither.
2. Starts from the closest shipped workflow (`quick`, `story`, `slice`, `triage`, `reproduce`, `refinement`), never from a blank file.
3. Writes `.agents/workflows/<name>.yaml` against a reference of step types, outcomes and rules that cannot drift from `packages/schema/src/workflow.ts`. Preferably that reference is generated by `docs:emit` into docs/reference.md, and the skill points at it (see #266 for the drift this avoids).
4. Validates with `norn doctor --repo --json`, the same validator a tick uses, and fixes every issue it reports (`unknown_target`, `unknown_counter`, `cannot_reach_done`, `unknown_skill`, `reserved_outcome`, …) until the workflow is clean.
5. Ends with the next steps: commit it, run `norn upgrade` for the label, then label an issue `norn:wf:<name>` or run `norn story edit gh-N --workflow <name>`.

Bundled in `packages/cli/assets/skills/` so `norn init` and `norn upgrade` ship it to users, who are the ones writing custom workflows.

## Where

- packages/schema/src/workflow.ts: the workflow schema
- packages/core/src/workflow.ts: the validator and its issue codes
- packages/cli/src/commands/doctor.ts:279: `--repo` runs repo workflows through `checkedRepoWorkflows`
- docs/recipes.md:93: "Write your own workflow"
- packages/cli/assets/workflows/: the shipped workflows to start from
