## Summary

The docs become a small set where each file has one reader and says each thing once. A newcomer follows the README to a first story. Every id'd rule lives in one rules file. Repo tests fail when a doc drifts from the CLI. Behaviour does not change: outside docs and tests, the code diff is comments only, plus the new Reference generator.

## Merge danger

**Door:** two-way: a revert restores the PRD, the SPEC files, the cookbook and the audits from git, and nothing outside the repo depends on the new paths.

**Blast radius:** in-flight branches. Some ways this could hurt:
- Open PRs that cite `.agents/PRD.md` or a `SPEC-*` file now fail the pointer lint.
- So do open PRs that add a command or flag without running `bun run docs:emit`, or that add a version string or a dead link to a doc.
- Running units keep their pinned workflow, which still says "amend the PRD". Only later rounds pick up the RULES.md instruction (S7).

Users of the released binary notice nothing.
