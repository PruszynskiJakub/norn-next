# Security checklist

Applied by the Standards axis when the diff touches a path the repo's `REVIEW.md` marks sensitive. Check every hunk under those paths, and any other hunk that reaches the same code, against each item. A breach is a bug: blocking, with the file, the line and the input or setup that triggers it.

- **Injection.** Outside input (a file, a branch or issue title, an env var, a CLI argument, a network reply) reaches a shell command, a query, a path, a regex or a template without being passed as data. Shell strings built by concatenation instead of an argument array; a path joined from input that can climb out with `..` or an absolute path; input used as a flag (a leading `-`).
- **Secrets.** A token, key or password committed, logged, printed in an error, written to a file other users can read, placed in a URL or command line (visible in `ps` and shell history), or sent to a service that does not need it. A test fixture holding a real secret.
- **Process spawning.** A child process started through a shell when it need not be; a program found on `PATH` where a fixed path or a resolved one is expected; a child that inherits the whole environment, open file descriptors or a working directory it should not; exit codes or stderr ignored so a failed step reads as success.
- **Env loading.** An env or dotenv file read from a place an attacker can write (the current directory, a checked-out branch, a temporary folder); its values trusted as code or as paths without checks; one file's values overriding another's in an order nobody chose; a variable that changes what runs (`PATH`, `NODE_OPTIONS`, `LD_PRELOAD`, a hook or editor command) taken from it.
- **The PATH shim.** A wrapper placed ahead of the real program on `PATH`: it must find the real program without finding itself, pass arguments through unchanged and quoted, keep the exit code, and never widen what the caller may do. A shim directory others can write to, or one left on `PATH` after it is needed, is a finding.
- **Tokens.** An access token with more scope than the work needs, stored in plain text, kept after it expires, reused across accounts, or passed to a child process or a log that does not need it. Tokens read from the CI context in a workflow that runs untrusted code (a pull request from a fork, a step that checks out its head).
- **CI workflows.** A workflow triggered by an untrusted event that runs with write permissions or secrets; an action pinned to a moving tag instead of a commit; `${{ }}` expressions from untrusted fields pasted into a `run` script instead of passed through `env`.
- **Persisted data.** A format change that lets a crafted file run code or escape its folder when read back, or a read that trusts a file's content without validating it.
