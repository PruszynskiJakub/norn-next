## Security and race fixes, through the real server: pass (`10/security.txt`, `10/race-lab-not-ready.txt`)
- `Host: evil.example:18737` on `GET /api/state`, `GET /` and `POST /api/act/reset` → 403 `foreign_host`.
- `Origin: http://evil.example` → 403 `foreign_origin`. `Sec-Fetch-Site: cross-site` → 403 `foreign_origin`.
- `content-type: text/plain` → 415 `not_json`.
- A plain curl POST with JSON and no Origin runs the command: `answer` came back 200 with `command` and `exit` (the command itself was then refused person_only).
- In headless Chrome, the page's own presses (same-origin) ran (`10/browser-press.json`).
- Started with `--clean` and POSTed `reset`, then `approve`, right after the URL printed → both 409 `{"code":"lab_not_ready","error":"reset needs the lab, and the lab is still being built"}`.
- Also checked: unknown button → 404 `unknown_action`, `answer` with no text → 400 `input_missing`, GET on an action → 405, any other path → 404.
- Observation: the Host check matches the name only, not the port. `Host: 127.0.0.1:9999` and `Host: localhost:18737` are accepted (200). That is harmless against DNS rebinding, since an attacker cannot make the name a loopback name, but it is looser than "loopback address:port".
