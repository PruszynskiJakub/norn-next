# 04.AC2 — person

Observed via `norn brief` (dev build, harness) in the unit worktree at implement after each send-back:

- after send-back 1: `fix round review.changes_requested 1/3`, no last-round line
- after send-back 2 (counter 2/3): `fix round review.changes_requested 2/3`, no last-round line
- after send-back 3 (counter 3/3): `**Last round on `review.changes_requested` (3/3):** if the work is sent back along it once more, the unit goes stuck.`
- a 4th send-back parks the unit (04.AC1).

So the warning names the derived counter and comes one send-back before stuck, but it reads (3/3), not the criterion's (2/3). Brief threshold logic (packages/core/src/brief.ts at_limit) is not changed by this story; named counters behave the same.
