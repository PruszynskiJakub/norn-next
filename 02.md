## AC4: every shipped workflow and this repo's own workflow files carry `when:`, and a test fails without one (test)

**Ran:**
- A grep of the `when:` key in each file.
- A mutation removing `when:` from `reproduce.yaml`, then `bun test packages/pack-sdlc/test/unit/load.test.ts`, then a revert. Log: `mutations/mut-02-AC4-loadtest.log`. More mutation logs: `mut-02-AC4.log`, `mut-02-AC4-reemitted.log` and `mut-02-AC4-other-workflows.log`.

**Saw:**
- Pack: `fix`, `quick`, `refinement`, `reproduce`, `slice`, `story` and `triage` each have a top-level `when:` key. None keeps a header comment.
- Repo: `.agents/workflows/release.yaml` and `.agents/workflows/triage.yaml` have **no `when:` key**. Their when-to-pick text is still a header comment. Commit `6419d3a8d` deliberately moved it back ("when: stays a comment there until a release reads it"), because the released `norn` that runs this repo's rounds refuses an unknown top-level key. `packages/cli/test/unit/this-repo.test.ts:84` now *requires* that no repo workflow has `when:`.
- The guard: removing `when:` from `reproduce.yaml` makes `(fail) … reproduce.yaml says when to pick it and what comes next in its when:` go red (`41 pass, 1 fail`). Reverted, and the tree is clean.
- Detail: only `load.test.ts` holds this. Other suites (reference, catalog, workflows-page) go red on a missing `when:` only for `quick`, or only through the docs stale check.

**Verdict: fail (partial), with an explicit reason.** The pack half and the guard pass. The "this repo's own workflow files" half is not met: `release.yaml` and `triage.yaml` carry the text as a comment, not as `when:`. This was a deliberate deviation for compatibility with the released binary, and a test now forbids the key. Repro: `grep -c '^when:' .agents/workflows/*.yaml` prints `0` for both. A person should either accept the deviation (amend the AC) or schedule the move once a release reads `when:`.
