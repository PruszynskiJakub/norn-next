# QA evidence: gh-517/11, break-it switches with their way out

HEAD `eb7891450`. Same setup as `10.md`: the dev `norn lab --clean --port 18737` ran in a fresh temp dir. Each switch was pressed with `curl -X POST -H 'content-type: application/json' -d '{}' http://127.0.0.1:18737/api/act/<name>`. The switch names, from `packages/cli/src/lab/break-it.ts` `BREAK_NAMES`, are `kill`, `fail-check`, `move-base`, `corrupt` and `expire-claim`. The state each switch produced was observed with the dev CLI's `status --json` and `tick --json`, run in the lab repo with the lab's own `NORN_HOME_DIR`.

**Limit of this run.** QA ran inside an agent session, so `norn story answer`, `norn run rerun` and `norn story take` were refused `person_only`, and that guard was not bypassed. The story stayed parked at beat 3 (the agent's question). So no check or base update ran after a switch, except where noted below.

## AC1: "kill the agent" stops the run's processes, and a later tick reports the agent died: pass
- After Reset, pressed `kill` every 0.4 s. While no agent ran, the answer was `lab_not_ready` "no agent of lt-1 is running" (`11/kill-attempts.txt`).
- During implement it answered `{"command":"kill -s KILL -- -10779","exit":0,"way_out":"Nothing to do: the next tick finds the agent's process gone and retries the step in a fresh session (rule `agent.died.retry` …). … `norn run rerun lt-1` runs it again."}` (`11/kill-answer.json`).
- Afterwards `ps -g 10779` listed no processes.
- The next decisions included `agent.died.retry` → "the agent's session ended without a report, so a fresh one starts" (`11/kill-decisions.txt`). The receipts show the extra `run.started` for the fresh session (`11/kill-receipts.txt`).

- The way out gives the exact revert line, then `norn run rerun lt-1`.
- In the worktree, `git log` showed `c945d76 norn lab: break the check on purpose`. `sh test.sh` printed `FAIL: the lab broke this test on purpose` and exited 1 (`11/fail-check-test-run.txt`).

The next check's output reads "FAIL: the lab broke this test on purpose" (not the beat-2 "greet.sh printed …"), and `check.fail` rises.
